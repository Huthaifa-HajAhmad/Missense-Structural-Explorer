# Predictor availability and local agreement

GATA4 p.Ser159Cys: UniProt P43694 lists the alternative NP_001295022.1 before the displayed sequence NP_002043.2. The popEVE resolver previously selected the first NP_ entry. It now resolves the displayed isoform, keeps the untagged canonical cross-reference as the correct mapping whenever the displayed isoform *is* the canonical one (Q3MIW9), and refuses to borrow another isoform's file (Q70EL3) rather than scoring the variant on the wrong numbering. A sampled 500 reviewed human entries showed 14 (5.8% of those with a displayed isoform and an NP_ cross-reference) that a tagged-only rule silently dropped; `NP_543146.2` and `NP_940881.3` are live popEVE files, so those were real scores reported as missing.

Live provider check on 29 October 2026: https://data.evemodel.org/popeve/v1.1/mutations/NP_002043.2.csv contains S159C = -3.376. This is an indeterminate reading under the existing popEVE rule. No engine voting policy or cut-point changed.

The gene lookup asks for the two fields it reads (`xref_refseq,cc_alternative_products`). Without that subset UniProt returns whole entries — sequences, features and every reference — and TP53 measured 1.36 MB per lookup. The search keeps a page of results and scans them for the first entry that yields a mapping: asking for a single entry (`size=1`) changed UniProt's ranking and returned an unreviewed duplicate with no RefSeq for GATA4 and GZF1, which would have been a new cause of missing popEVE scores.

Comparison and Details now expose local descriptive agreement with coverage, named contributors and missing sources. Native/alternate LLR preference is described separately from published clinical bands; a calibrated non-voting code is named as a published band, not a counted vote. AVI, Eigen, DANN and ConSurf receive no invented directional cut-point. No average or independent-evidence claim is made, and an absent or unclassified reading is stated only when it exists. The tab card and the inspector rail render the same shared note list, so the wording cannot drift.

Other missing provider fields (including ESM-1b and Eigen) remain missing; no scores are imputed. Existing persisted analyses need a fresh analysis to obtain the corrected popEVE lookup.

Validation: `npm run lint` (boundaries, focus indicators, verify parity, `tsc --noEmit`) passed; full Vitest 6011 passed, 5 skipped, 0 failed across 464 files; the predictors browser check passed at 1440 and 800 pixels in light and dark. A live probe through the shipped resolver returned NP_002043.2 for both `GATA4` (gene path) and `P43694` (accession path), NP_543146.2 for `Q3MIW9`, and null for `Q70EL3`.
