# Review — 2026-10-29

Four read-only reviewer lanes ran over the uncommitted change set: the Functional-domains **Hotspots**
subtab, the **3D-clustering** score, the **published PP2 calibration** replacing the in-house rule, the
Interfaces lanes, and the 3D viewer's **"On this canvas"** card. This file records what each lane found and
what happened to it. Findings that sit outside the change are named as follow-ups, not silently dropped.

## Method

| Lane | Question | Scope |
| --- | --- | --- |
| Scientific rigour | Does each claim match its source, and is an unrun test ever reported as a negative? | `hotspotEvidence.ts`, `spatialClustering.ts`, `perBurden.ts`, `perRegions.ts`, `cspecPm1.ts`, `thresholds/calibration.ts`, `server/services/evidence-context/*`, the two decision docs |
| Contracts & data flow | Can a payload, key or rejection break a caller? | `contracts.ts`, `evidenceKeys.ts`, `useEvidenceContext.ts`, the prefetch, the route, the worker, `MolstarViewer` |
| UI / UX / a11y | Is every state honest and every control reachable? | `HotspotsView`, `StructureGuideCard`, `InterfaceTrack`, `AssemblyDiagram`, the rails, the stylesheets |
| Tests / DX / AX | Would a regression be caught, and can a person or an agent run the proof? | new and changed tests, fixtures, `e2e.config.ts`, benchmark scripts, `package.json`, docs |

Procedure: reproduce each finding against the source before acting on it; fix inside the change; record
anything outside it. Repo posture `.agents/rules/review-posture.md` was applied: a review produces findings,
a bug hunt may only edit inside the reviewed surface.

## Blockers that were real

1. **Any source that throws could end the process.** `server/routes/evidence-context.ts` awaited its loader
   with no `try/catch`; Express 4 does not forward a rejected async handler, and there is no
   `unhandledRejection` handler. The new PER table is read with `readFileSync` inside that path, so one
   missing file would have taken the server down for every request. Fixed at the route, and the PER read now
   degrades to its own rung (`unavailable`) rather than rejecting the whole payload.
2. **A published region that could not be placed was reported as "outside".** If every Pérez-Palma region was
   withheld for sequence mismatch, the rung still said the residue lay outside the regions — a test that never
   ran, published as a negative. It now returns `not-shown` with no verdict.
3. **A failed ClinVar read read as "no P/LP variants in this protein".** The distribution rung said "provider
   error", the residue table said the opposite. The empty-table sentence is now conditional on the
   distribution succeeding.

## Documented, not changed — with the reason

- **`isPP2Constrained: false` + `pp2Code: null` cannot distinguish "not assessed" from "assessed, below band".**
  `regionalStatus` already carries that distinction (`unverified-locus`, `outside-region`, `failed-qc`,
  `nonsignificant`, `measured`), and `regionalConstraint` is null unless the interval was measured. Adding a
  second field would duplicate it. Consumers that read the boolean alone lose the nuance; none in this tree
  does.
- **The 3D self-check is in-sample, and the bivariate null can contain a residue twice.** Both are now stated
  in `doc/HOTSPOT_3D_DECISION.md`. Changing the statistic would invalidate the pre-registered numbers, so it
  is an owner decision with a new registration, not a review fix.
- **`FunctionTab` does not offer a Retry for a failed hot-spot read.** Wiring `useEvidenceContext` into the tab
  pulled `SettingsProvider` into a leaf component and broke its own tests. The spinner-forever cause is fixed
  (the read no longer requires a UniProt); retry needs a loader prop threaded from the workspace, which is a
  larger change than this review should carry.
- **The annotation table's 3D buttons still offer a structure when AlphaFold has no model.** The ESMFold tab
  may still have one, so hiding them would be wrong there; only the hotspot table is gated.
- **`sod1.spatial.status` is asserted as a precondition inside a test.** It documents the fixture; moving it
  to a `beforeAll` would not change what can regress.

Every finding below was reproduced before it was acted on.

RSA is a percent with no burial word, because those cut-points are the app's own |
| Failed hot-spot read had no Retry | `readHotspots` is the one reader for the prefetch, the hook and a leaf `HotspotsRetry` button ("Try again" on a failed read, "Read again" naming the source on an incomplete answer) |

| Python and TypeScript PER parity was asserted, not executed | `perBurdenParity.test.ts` against `perBurdenGolden.json`, generated by `scripts/hotspot_probe/make_golden.py` (SOD1, VHL and two synthetic cases that exercise the region merge). Both ports agree on windows, regions and p-values to 1e-9. The 3D probe is not covered: its permutation p-values use a different RNG |
| `ContextualCoverage` could flake | The dashboard's real client retried in jsdom and wrote the singleton store after the test. The file now mocks the client with a hoisted never-settling `fetchWithAuth`, whose stable identity is what keeps the readers' effect from re-running |
| `doc/GNOMAD_CONSTRAINT.md` still described the retired PP2 rule | Rewritten to the calibrated rule |
| The published-region file was untracked | Committed with `server/data/per/README.md` (provenance, licence, limits) |
| PER licence and gnomAD ClinVar scope unresolved | Checked against the sources: `plan §5` |

Two corrections to this ledger's own claims, found while doing the above:

- **"The read no longer requires a UniProt" was not true.** `useEvidenceContext` still gated it on `uniprot &&`, so a result
  without one sat on "Reading…" forever. The gate is gone, and a test pins that the prefetch asks for the bare endpoint.
- **The cache decision above is reversed in part.** "Evict only when the variant rows themselves failed" made a transient
  CSpec or AlphaFold failure stick for 24 hours, so Retry could not repair it. A degraded answer is now not cached, and the two
  expensive computations (the 3D statistic and the accessibility run) are memoized on their inputs instead, which keeps what
  that decision protected: repairing one rung does not redo them. The memo only keeps answers: a resolved `{status: "error"}`
  from the accessibility tool is dropped, which a test now pins (it was being kept for 24 hours before the test existed).

## What could not be verified here

- **No rendered pass.** No browser, screenshot or contrast sampling; contrast figures are computed from the
  design tokens, and hit sizes from CSS.
- **The literature was not re-read.** The PP2 edges (0.36 / 0.59 / 0.97 / 1.23) were checked for internal
  consistency with `calibration.ts` and the decision doc, not against Chao et al. v3 itself.
- **No live provider run.** Provider-error paths are exercised with injected failures, not with gnomAD,
  ClinVar, CSpec or AlphaFold actually down.
- **The e2e proof suite was not executed.** It needs a dev server, WebGL and live providers; only its
  selectability was proven, and the new command was not run end to end.
- **The 3D benchmark was not re-run.** The recorded result and its threshold hash are now pinned by a test,
  which is not the same as re-deriving the numbers on this machine.
